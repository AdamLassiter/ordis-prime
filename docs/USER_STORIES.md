# User story map

## Acquisition explorer — first release

- As a guest, I can search for an item and follow its recipe to every required
  component and documented acquisition source.
- As a guest, I can open a node and see every linked reward, chance and rotation.
- As a player, I can record quantities, built and wanted copies, and optional
  mastered or subsumed state.
- As a player, I can filter a node to rewards I still need.
- As a player, I can record completion for a filtered group of star-chart nodes
  without changing nodes hidden by those filters.
- As a player, I can set goals and receive candidate nodes with a visible reason,
  rather than an unexplained score.
- As a player, I can see whether my inventory meets a cited node-entry quantity
  and follow that item back to every node that requires it.
- As a player, I can record my current adversary and see only the matching final
  confrontation as available while unrecorded state stays conditional.
- As an administrator, I can see dataset freshness, import failures, conflicts
  and the exact upstream record behind a fact.

## Time-aware planning and builds

- As a player, I can keep static todos and create live-state watches that emit
  one private alert per matching occurrence.
- As a player, I can save partial or complete loadouts with item-specific mods
  and notes, then share an immutable revision without exposing my draft.
- As a player, I can compare my positioned build slots with cited factory
  polarity roles and counts without the application inventing source positions.
- As a player, I can turn missing equipment and mod quantities in a build into
  acquisition goals without overwriting larger plans.
- As a guest, I can compare independently cited tier lists without hidden scale
  conversion or a synthetic consensus.

## Later consumers of the same graph

- Live windows intersect with goal-backed node recommendations to surface
  expiring acquisition opportunities in the planner.
- Quest and mechanic prerequisites surface systems a player has not discovered.
- A visual star chart uses the same node IDs, edges, filters and planner queries.
